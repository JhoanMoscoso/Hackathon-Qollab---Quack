PLACEMENT RULES
- H, C, M, D and S are gameplay objects. Do not replace, move, or rename them if the existing code
  references fixed coordinates; use this map only after mapping these symbols to current coordinates.
- Decorations never modify quantum state, gate order, measurements, door state, or collision logic.
- Keep a clear walking lane at least one tile wide from each spawn to its console and exit.
- Do not put tanks, plants, desks, rugs, or conduits on top of H/C/M/D/S or spawn tiles.
- Suggested tank footprint is 2x2 tiles; plant 1x2; desk/computer 2x2. These are footprints, not single symbols.
  Reserve all covered tiles when placing a large prop in the actual renderer.
- Columns 9 and 10 remain the central divider as specified by the integration guide. Existing passages
  through the divider must be preserved by the game's current map/collision data.
- The ASCII grid is a conceptual layout guide; because props can occupy multiple tiles, use the
  placement list below as the authoritative decoration placement proposal.

IMPLEMENTATION SAFETY
1. Keep decorations in a separate `decorations` layer/list; don't encode them as gate/door entities.
2. Draw floor and wall tiles first, then decorations, then interactive consoles/doors, then players and effects.
3. Decorations should be non-interactive by default. If a desk is intended to block movement, explicitly mark its footprint solid.
4. Don't change event handlers or quantum-engine calls while adding decorations.
5. Test movement from each spawn to H/CX, measurement, and exits. Confirm no decoration overlaps a hitbox.
6. Render at nearest-neighbor / `imageSmoothingEnabled = false`.
